# El7a2ny Car Service Platform

Production-oriented monorepo for a car service platform serving Customer, Admin, and Super Admin roles. It includes web and mobile applications, an Express API, authentication, and a PostgreSQL domain model managed through Prisma.

## Architecture

The repository uses pnpm workspaces and Turborepo. It contains six independent React frontends, one modular-monolith Express backend, and focused shared packages under the `@car-platform/*` namespace.

- Web applications use React, Vite, TypeScript, and React Router.
- Mobile applications use React Native, TypeScript, and React Navigation, with native Android and iOS projects generated by the React Native Community CLI.
- The backend uses Node.js, Express, TypeScript, Prisma ORM, and PostgreSQL.
- Shared web and mobile UI packages remain separate.

## Backend

The backend is a modular Express application in `backend/`. It exposes `GET /health` and authentication endpoints under `/api/auth`. Features live in `src/modules`; each module keeps its routes, controllers, business services, repositories, validation, and feature-specific helpers together.

Backend responsibilities are organized as follows:

- `src/config` centralizes environment access and database initialization.
- `src/modules` contains feature modules. Requests flow from routes to controllers, services, repositories, and Prisma.
- `src/middleware` contains shared HTTP concerns such as authentication, validation, rate limiting, and error handling.
- `src/errors` contains application-level error types.
- `src/routes` composes module routers while each module owns its endpoint definitions.
- `prisma` contains the schema, migrations, and development seed.

## Shared packages

- `@car-platform/api-client` — framework-independent HTTP client foundation
- `@car-platform/types` — shared type entry point
- `@car-platform/validation` — shared Zod entry point
- `@car-platform/auth` — authentication utilities entry point
- `@car-platform/permissions` — permissions entry point
- `@car-platform/utils` — framework-independent utilities entry point
- `@car-platform/constants` — framework-independent constants entry point
- `@car-platform/ui-web` — React web components entry point
- `@car-platform/ui-mobile` — React Native components entry point
- `@car-platform/eslint-config` — reusable ESLint flat configurations
- `@car-platform/typescript-config` — base, web, mobile, and Node TypeScript configurations

## Prerequisites

- Node.js 22.13+ or 24.3+ (use a React Native-supported release line)
- Corepack, with pnpm enabled (`corepack enable`)
- PostgreSQL for database work
- Android Studio, Android SDK, and JDK 17 for Android development
- macOS, Xcode, Bundler, and CocoaPods for iOS development

## Installation

```bash
corepack enable
pnpm install
cp .env.example backend/.env
```

If Corepack cannot install system shims, run `corepack pnpm install` and prefix the other pnpm commands with `corepack`. Update `backend/.env` with a valid PostgreSQL connection string before running database commands. On Windows, copy the file with `Copy-Item .env.example backend/.env`.

On Windows, enable Win32 long paths or keep the checkout near the drive root before building `super-admin-mobile`; New Architecture C++ object paths can otherwise exceed the legacy 260-character limit. iOS builds and CocoaPods installation must be run on macOS with Xcode.

## Development commands

Run commands from the repository root:

```bash
pnpm dev
pnpm build
pnpm lint
pnpm test
pnpm typecheck
pnpm format
```

Run one workspace when that is more convenient:

```bash
pnpm --filter @car-platform/backend dev
pnpm --filter @car-platform/customer-web dev
pnpm --filter @car-platform/customer-mobile start
pnpm --filter @car-platform/customer-mobile android
pnpm --filter @car-platform/customer-mobile ios
```

Prisma commands:

```bash
pnpm --filter @car-platform/backend prisma:validate
pnpm --filter @car-platform/backend prisma:generate
pnpm --filter @car-platform/backend prisma:migrate
pnpm --filter @car-platform/backend prisma:seed
```
